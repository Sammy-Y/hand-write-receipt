# PRD：台灣手寫統一發票開立小幫手

> 版本：1.0（2026-07-25 回補）
> 狀態：開發中

## 1. 背景與問題

台灣仍有許多小型商家、攤商在停電、機器故障或未導入收銀系統時需要**手寫統一發票**。手寫發票最容易出錯的地方：

1. **稅額計算**：三聯式發票需拆分「銷售額（未稅）／營業稅 5%／總計」，口算或計算機按錯很常見，尾數處理（四捨五入）也常搞錯。
2. **金額中文大寫**：總計欄需以中文大寫（壹貳參肆…）書寫，跨位補「零」的規則（如 10,500 → 壹萬**零**伍佰元整）容易寫錯。
3. **含稅反推**：客人只講含稅總價時，要反推銷售額與稅額，且三者相加不能出現一元尾差。

本產品是一個**純前端網頁工具**：使用者輸入品項或金額，即時得到正確的稅額拆分與中文大寫，照著抄到紙本發票上即可。

## 2. 目標與非目標

### 目標

- 開立手寫發票時**零心算**：所有金額欄位（銷售額、營業稅、總計、中文大寫）自動算好。
- **雙向計算**：可以從未稅銷售額算總計，也可以從含稅總計反推。
- 保證 `銷售額 + 營業稅 === 總計`，絕不出現尾差。
- 手機上單手可操作（攤商情境多為手機）。

### 非目標

- 不儲存任何資料、不做發票號碼管理、不做進銷存。
- 不串接財政部電子發票系統（本工具服務的是「紙本手寫」情境）。
- 不處理免稅／零稅率／特種稅額（僅一般應稅 5%）。

## 3. 使用者

- 小型商家老闆、攤商、臨時需要手寫發票的店員。
- 特徵：非財會背景、常用手機、需要「照著抄」等級的明確輸出。

## 4. 功能需求

### 4.1 發票類型切換（Tab）

| 類型 | 說明 |
|---|---|
| 三聯式 | 買受人為營業人（有統一編號），需拆分銷售額／營業稅／總計 |
| 二聯式 | 買受人為一般消費者，僅填含稅總計，稅額內含 |

- 以 tab 切換，預設三聯式。
- 三聯式顯示「統一編號」輸入欄（8 碼）；二聯式隱藏。

### 4.2 買受人資訊

- 買受人名稱（文字輸入）。
- 統一編號（僅三聯式，8 碼數字）。
- 僅供畫面上對照抄寫，不做進階驗證（統編檢查碼為 nice-to-have）。

### 4.3 品項表格（ItemsTable）

- 欄位：品名、數量、單價、金額（= 數量 × 單價，自動計算、唯讀）。
- 可新增／刪除列。
- 數量或單價未填時該列金額視為 0。
- 品項合計自動帶入金額面板：三聯式帶入**銷售額**（品項視為未稅價），二聯式帶入**總計**（品項視為含稅價）。

### 4.4 金額面板（AmountPanel）與雙向計算

- **三聯式**：
  - 銷售額（可編輯）→ 營業稅 = round(銷售額 × 5%)，總計 = 銷售額 + 營業稅。
  - 總計（可編輯）→ 銷售額 = round(總計 ÷ 1.05)，營業稅 = 總計 − 銷售額。
  - 營業稅欄唯讀。
- **二聯式**：僅總計輸入框，下方小字顯示內含稅額與銷售額（供記帳參考）。
- 面板底部大字顯示**總計中文大寫**（如「壹萬零伍佰元整」），為本產品最核心的抄寫輸出。
- 所有金額為整數元；金額顯示加千分位。

### 4.5 稅務計算規則（`src/lib/invoice.ts`）

- 稅率固定 5%（`TAX_RATE = 0.05`）。
- 依《加值型及非加值型營業稅法施行細則》第 32-1 條，稅額尾數不滿一元者**四捨五入**。
- 含稅反推：`銷售額 = round(總計 / 1.05)`、`稅額 = 總計 − 銷售額`，以減法保證三者相加無尾差。
- 非法輸入（負數、NaN、Infinity）一律視為 0。

### 4.6 金額中文大寫（`toChineseUpper`）

- 數字：零壹貳參肆伍陸柒捌玖；單位：拾佰仟／萬億兆。
- 尾綴「元整」；0 → 「零元整」。
- 跨位補零規則正確（10500 → 壹萬零伍佰元整；100001 → 壹拾萬零壹元整）。
- 支援 0 ～ 9999 兆；超出範圍或非整數回傳空字串。

### 4.7 清除

- 一鍵清除所有輸入（買受人、品項、金額），回到初始狀態。

## 5. 非功能需求

- **純前端**：無後端、無資料庫、不收集任何資料，可靜態部署。
- **RWD**：手機優先，品項表格窄螢幕可橫向捲動。
- **語言**：繁體中文（台灣用語）。
- **效能**：所有計算即時（同步、無網路請求）。

## 6. 技術方案

| 項目 | 選型 |
|---|---|
| 框架 | Vue 3（`<script setup>` + TypeScript） |
| 建置 | Vite 8 |
| 樣式 | Tailwind CSS 4 + daisyUI 5 |
| 單元/元件測試 | Vitest + @vue/test-utils（happy-dom） |
| e2e 測試 | Playwright |
| 部署 | Vercel（靜態站） |

### 元件架構

```
App.vue                  ── 狀態中樞：invoiceType / buyer / items / breakdown
├── ItemsTable.vue       ── 品項表格，v-model:items
└── AmountPanel.vue      ── 金額面板，emit update:sales / update:total
```

- 計算邏輯全部收在 `src/lib/invoice.ts`（純函式），元件只負責呈現與事件。

## 7. 驗收標準

1. 三聯式輸入銷售額 10,000 → 營業稅 500、總計 10,500、大寫「壹萬零伍佰元整」。
2. 三聯式輸入總計 10,500 → 反推銷售額 10,000、營業稅 500。
3. 任何金額下 `銷售額 + 營業稅 === 總計`。
4. 二聯式僅顯示總計輸入，內含稅額正確。
5. 品項增刪、數量單價變動即時反映合計與大寫。
6. 清除鍵一鍵歸零。
7. 單元測試、元件測試、e2e 測試、`vue-tsc` 型別檢查與 production build 全數通過。
