# PRD：台灣手寫統一發票開立小幫手

> 版本：1.0.0（2026-07-25）
> 狀態：功能全部完成，測試與型別檢查、production build 全數通過；**尚未部署**（唯一未完成項）
> 版面與互動的權威規格：**[`docs/ui-spec.md`](./ui-spec.md)**。本 PRD 只描述產品範圍與行為，版面細節（欄寬比例、格線粗細、配色、`data-testid` 契約、刻意為貼合紙本而保留的呈現方式）一律以 ui-spec 為準，兩份文件若有出入，以 ui-spec 與實作為準。

## 1. 背景與問題

台灣仍有許多小型商家、攤商在停電、機器故障或未導入收銀系統時需要**手寫統一發票**。手寫發票最容易出錯的地方：

1. **稅額計算**：三聯式發票需拆分「銷售額（未稅）／營業稅 5%／總計」，口算或計算機按錯很常見，尾數處理（四捨五入）也常搞錯。
2. **金額中文大寫**：總計欄需以中文大寫（壹貳參肆…）逐位填入九格「億仟佰拾萬仟佰拾元」，位數對錯格、跨位漏零都很常見。
3. **含稅反推**：客人只講含稅總價時，要反推銷售額與稅額，且三者相加不能出現一元尾差。

網路上的同類計算機欄位都寫死、不能改，算出來的數字還要自己對應到紙本的哪一格。本產品的差異是：**畫面與紙本統一發票同規格，而且每一格都能自己填**——品名、數量、單價、每列金額、備註、銷售額、營業稅額、總計、應稅／零稅率／免稅、買受人、統編、地址、開立日期、期別全部可改。自動計算只是輔助帶入，使用者隨時可手動覆寫任何一格，照著螢幕抄到紙本上即可。

## 2. 目標與非目標

### 目標

- **版面與紙本同規格**：使用者不需要在「工具的欄位」與「紙上的格子」之間換算位置，一格對一格照抄。
- **零心算**：銷售額、營業稅額、總計、中文大寫九格全部自動帶入。
- **每一格都可覆寫**：包含所有衍生欄位（每列金額、銷售額、營業稅額、總計）。自動計算不得綁死使用者。
- **雙向計算**：可從未稅銷售額往下算，也可從含稅總計往上反推。
- 保證 `銷售額 + 營業稅額 === 總計`，絕不出現一元尾差。
- 支援**應稅 5%／零稅率／免稅**三種課稅別。
- 不儲存任何資料，開網頁就能用。

### 非目標

- 不儲存任何資料、不做發票號碼管理、不做進銷存、不做帳務彙總。
- 不串接財政部電子發票系統（本工具服務的是「紙本手寫」情境）。
- **不處理特種稅額**（非加值型／特種飲食業等特種稅率）；課稅別只做應稅 5%、零稅率、免稅三種。
- 不做列印／PDF 匯出（產出是「抄到紙本」，不是印一張出來取代發票）。
- 不驗證統一編號檢查碼（欄位只限制「阿拉伯數字」與長度）。
- 民國日期的月／日會驗證是否為真實存在的日期並自動夾到合法範圍（詳見 4.3），但**不**做「填了日期就必須早於／晚於今天」之類的日期先後邏輯驗證。
- 不做多語系、不做使用者帳號。
- 金額欄位離開聚焦（blur）後**加千分位**顯示，聚焦編輯中則顯示純數字（詳見 4.9）；數量、期別年份、民國日期年月日不加千分位。

## 3. 使用者

- 小型商家老闆、攤商、臨時需要手寫發票的店員與行政人員。
- 特徵：非財會背景，習慣看紙本發票的版面，需要「照著抄」等級的明確輸出。
- 裝置：桌機與手機皆可。手機上**版面不重排**（跟紙一樣，橫向捲動查看），這是刻意取捨——貼合紙本優先於單手操作便利性。

## 4. 功能需求

### 4.1 發票類型切換（Tab）

| 類型 | 說明 |
|---|---|
| 三聯式（預設） | 買受人為營業人（有統一編號）。有統一編號欄、銷售額合計列、營業稅列（應稅／零稅率／免稅）、總計列 |
| 二聯式 | 買受人為一般消費者，稅額內含。無統一編號欄、無銷售額合計與營業稅列；改在**發票框外**以小字顯示「內含稅額 $X｜銷售額 $Y」供記帳參考 |

- 以 tab 切換，預設三聯式。tabs 可用鍵盤操作（Tab 聚焦、Enter／Space 切換），並以 `aria-selected` 標示目前選取。
- 切到二聯式時，課稅別強制回「應稅」並重算：二聯式版面沒有任何稅制欄位，若沿用三聯式選的零稅率／免稅，畫面上既看不到也改不回來，框外內含稅額會永遠是 $0。
- 切換時品項合計 > 0 則依新模式重算（三聯式視為未稅、二聯式視為含稅），否則沿用現有金額。期別、開立日期、買受人、品項內容在切換時一律保留。

### 4.2 期別（標題下方）

- 一行置中的「[民國年] 年 [雙月期] 月份」。
- **年份可填**：阿拉伯數字最多 3 碼，預設當年民國年（西元 − 1911）。
- **月份為下拉選單**：固定六個雙月期，顯示「一、二」「三、四」「五、六」「七、八」「九、十」「十一、十二」，值為該期起始月（1／3／5／7／9／11），預設依系統當月推算所屬雙月期。
- 期別年份與買受人區的開立日期年份**各自獨立**（跨期補開發票時常常不同年）。

### 4.3 買受人資訊與開立日期

- 買受人名稱、統一編號（僅三聯式，最多 8 碼、數字鍵盤）、地址，皆為自由輸入。
- **民國日期行**「中華民國 [年] 年 [月] 月 [日] 日」：年／月／日**三格全部由使用者填**；年預設當年民國年，月與日預設空白。此行水平置中於發票紙張寬度（窄螢幕會獨立成行，仍保持置中）。
- 期別年份與開立日期的年／月／日**只收阿拉伯數字**：非數字字元即時濾除並同步寫回畫面（`abc` → 空白、`9a` → `9`、`中文` → 空白），避免畫面殘留無效字元。
- **開立日期合法性驗證**：不得出現不存在的日期（例如 8 月 32 日）。月只接受 1～12，超出即夾到 12；日只接受 1～該月天數，超出即夾到上限（天數依民國年換算西元年判斷閏年，二月為 28 或 29 日，月份未填時上限以 31 計）；修改月份或年份後，若既有的日已超出新上限，日會跟著夾到上限（例：日 31、月改成 2 → 28 或 29；日 29、年由閏年改為平年 → 28），夾值結果同步寫回畫面。期別年份不受此規則影響（僅維持 3 碼數字限制）。不做統編檢查碼驗證（見 2. 非目標）。

### 4.4 品項表格

- 欄位：品名｜數量｜單價｜金額｜備註。
- **固定五列**，貼合紙本；**沒有新增／刪除列按鈕**（發票紙上就是五列）。
- **品名**（五列）與**備註**（僅第 1、2 列）為自動增高的 textarea：可手動換行，長字串自動換行且不截斷，該列列高與格線隨內容延展。視窗寬度或字級改變時會重新計算高度，避免舊高度配上溢出隱藏而吃字。
- **備註欄只有前兩列可填**：第 3 列為印刷字「營業人蓋用統一發票專用章」，第 4 列起是單一合併的空白蓋章區，一路延伸到中文大寫列（讓發票外框完整封閉右下角）。
- 數量／單價為數字輸入，允許小數（秤重、單價含角），清空即視為未填。
- **金額欄也是輸入框**：
  - 預設自動顯示 `round(數量 × 單價)`。
  - 直接輸入即為**手動覆寫**該列金額；之後再改該列數量或單價會清除覆寫、回到自動計算；清空金額欄同樣回到自動計算。
  - 顯示規則：未覆寫且金額為 0 → 依紙本**留白**；明確填 0（例如贈品列）→ 顯示 `0`。
- 品項合計（覆寫優先加總）自動帶入金額區：三聯式帶入**銷售額**（視為未稅），二聯式帶入**總計**（視為含稅）。**合計為 0 時不覆蓋已填的金額**——否則使用者只填金額區、不填品項時金額會被清掉。

### 4.5 金額區與雙向計算

三聯式的銷售額、營業稅額、總計與二聯式的總計**全部是可編輯欄位，沒有唯讀欄**（唯一唯讀的是中文大寫九格與二聯式框外的參考數字）。

- 連動規則：
  - 改**銷售額** → 應稅：稅額 = `round(銷售額 × 5%)`；零稅率／免稅：稅額 = 0。總計 = 銷售額 + 稅額。
  - 改**總計** → 應稅：銷售額 = `round(總計 ÷ 1.05)`、稅額 = 總計 − 銷售額；零稅率／免稅：銷售額 = 總計、稅額 = 0。
  - 改**營業稅額**（手動覆寫）→ 總計 = 銷售額 + 稅額，銷售額不動。
  - 切換**課稅別** → 以現有銷售額重算稅額與總計。
- 課稅別「應稅｜零稅率｜免稅」為紙本上的三個打勾格（radio 行為），選中者顯示「✓」，預設應稅。三格皆可鍵盤操作（Tab 聚焦、Enter／Space 選取，`aria-pressed` 標示狀態）。
- 二聯式金額區只有總計列與大寫列；內含稅額與銷售額顯示在發票框外（不屬於紙本欄位，不放進發票框內）。

### 4.6 金額中文大寫（發票內九格）

- 發票最後一列為「總計新臺幣（中文大寫）」＋九格印刷單位字「億 仟 佰 拾 萬 仟 佰 拾 元」。
- 依總計逐位填入大寫數字（零壹貳參肆伍陸柒捌玖），數字顯示在該格單位字**之前**；高於最高有效位的格子只留印刷單位字。
  - 例：10500 → 億／仟／佰／拾 只有單位字，其後為「壹萬 零仟 伍佰 零拾 零元」。
- **數字以手寫墨藍色（`#1d4ed8`）標示**、字級略大略粗，與橄欖綠印刷單位字明顯區隔，方便照著抄。
- 唯讀，永遠自動跟隨總計。總計 ≤ 0、非整數或超過九位數時，九格只剩印刷單位字（安全降級為不顯示，不會印出錯誤數字）。
- 位數少時整串大寫會偏右、左側單位字留空，這與紙本寫法一致，是**刻意保留**的呈現（見 ui-spec §2.5，勿「修正」為整組置中）。
- **空格橫線槓掉（2026-07-25 新增）**：總計有值時，高於最高有效位、留空的格子（例：總計 3,570 時的億／仟／佰／拾／萬）會以一條橫貫該格的橫線槓掉，線色同 olive 印刷墨；印刷單位字仍維持可見，不會被線蓋掉或隱藏。總計為 0 或空白時九格一律不劃線。
- 另有 `toChineseUpper()` 純函式可產生「壹萬零伍佰元整」單行字串（含跨位補零規則，支援 0 ～ 9999 兆），目前僅作為程式庫函式與單元測試對象，畫面上不呈現——發票紙上要填的是九格，不是一整句。

### 4.7 清除重填

一鍵清除，涵蓋範圍：

- 買受人名稱、統一編號、地址 → 清空。
- 開立日期：年回**當年民國年**，月與日**清空**。
- 期別：年回當年民國年，月份回**當期**雙月期。
- 五列品項：品名、數量、單價、金額覆寫、備註全部清空。
- 銷售額、營業稅額、總計歸零（畫面留白），中文大寫九格只剩印刷單位字。
- 課稅別回「應稅」。
- **不變動發票類型**：目前選的三聯式／二聯式維持不變。

### 4.8 稅務計算規則（`src/lib/invoice.ts`）

- 稅率固定 5%（`TAX_RATE = 0.05`）。
- 依《加值型及非加值型營業稅法施行細則》第 32-1 條，稅額尾數不滿一元者**四捨五入**。
- 含稅反推：`銷售額 = round(總計 ÷ 1.05)`、`稅額 = 總計 − 銷售額`，以減法保證三者相加無尾差。
- 零稅率／免稅：稅額固定 0、總計 = 銷售額。
- `normalizeMoney()`：所有寫入金額欄位的路徑都必須先過這一關——非有限數（NaN／Infinity）、負數與 0 一律視為 0，小數四捨五入為整數元。發票金額是整數元，否則會印出 `47.99000000000001`，且非整數會讓中文大寫九格整排空白。
- 民國年與期別：`rocYear()`（西元 − 1911）、`periodStartMonth()`（月份 → 所屬雙月期起始月，超出範圍回 1）、`PERIOD_START_MONTHS = [1, 3, 5, 7, 9, 11]`。

### 4.9 金額顯示規則

- **加千分位的欄位**：各列金額、單價、銷售額、營業稅額、總計，以及二聯式框外的內含稅額／銷售額（`formatMoney()`）。**不加千分位**：數量（是計數不是金額）、期別年份、民國日期年月日。
- **編輯中不加、離開欄位才加**：欄位取得 focus 時顯示純數字（方便編輯、游標不會亂跳），blur 後顯示千分位；使用者未在編輯的欄位（例如被連動更新的銷售額／稅額）一律顯示千分位。這些欄位改用 `type="text"` 搭配 `inputmode`（整數金額 `numeric`、單價 `decimal`），因為 `type="number"` 無法顯示逗號。
- 解析輸入時先剝除千分位逗號再正規化，貼上「10,500」會被正確解析成 `10500`，不會被當非數字歸零。單價允許小數，千分位只加在整數部分（如 `1,234.5`）。
- 金額 0 依紙本**留白**；唯一例外是列金額被明確覆寫為 0 時顯示 `0`（贈品列需要寫 0）。
- 使用者輸入的負數與小數會即時正規化並**同步寫回畫面**（`-100` → 留白或 `0`、`100.5` → `101`），避免畫面數字與實際計算值不一致。

## 5. 非功能需求

- **純前端**：無後端、無資料庫、不收集任何資料、無網路請求，建置產出為靜態檔案，可放任何靜態託管。
- **RWD**：發票區塊外層水平捲動、內容最小寬度約 640px。窄螢幕（實測 375px）以**橫向捲動**呈現，**版面不重排**；統一編號 8 碼不得被裁切，日期行獨立成行仍置中。
- **鍵盤可操作**：發票類型 tabs 與三個課稅別打勾格皆可聚焦並以 Enter／Space 操作；期別年份與月份下拉、開立日期三格皆有 `aria-label`。
- **視覺穩定**：發票區塊配色固定（米黃紙 `#f5f3e7`／橄欖墨 `#6b6414`／手寫墨藍 `#1d4ed8`），不隨深淺色主題變動。
- **無執行期錯誤**：自動增高流程（長品名、逐字輸入、連續縮放視窗、字級變動、切換聯式、清除重填）全程不得產生 console error、page error 或 window error，特別是不得出現 `ResizeObserver loop completed with undelivered notifications`。
- **效能**：所有計算為同步純函式；production bundle 約 76 KB JS（gzip 29 KB）＋ 43 KB CSS（gzip 8 KB）。
- **語言**：繁體中文（台灣用語），`<html lang="zh-Hant-TW">`。

- **單向資料流**：`InvoiceSheet` 只負責呈現與 `emit update:*`，所有狀態寫入都經 `App.vue` 的連動函式，再經 `lib/invoice.ts` 的純函式（含 `normalizeMoney`）正規化後寫回。
- v1.0 已**刪除** `ItemsTable.vue` 與 `AmountPanel.vue`：整張發票改由單一 `InvoiceSheet.vue` 依紙本版面渲染，不再拆成「品項表格 + 金額面板」兩個自創區塊。
- `data-testid` 契約（元件測試與 e2e 共用）定義於 ui-spec §5，改欄位前先看那份清單。

## 7. 驗收標準

以下每條都對應現有自動化測試（`tests/unit/**/*.test.ts`、`tests/e2e/invoice.spec.ts`）：

1. **三聯式正算**：數量 2 × 單價 5000 → 列金額 10000、銷售額 10000、稅額 500、總計 10500；大寫九格為「億／仟／佰／拾／壹萬／零仟／伍佰／零拾／零元」，億～拾萬四格無數字。
2. **含稅反推**：總計輸入 10500 → 銷售額 10000、稅額 500。
3. **恆等式**：`fromTotal` 掃 1～10000 每個整數皆 `銷售額 + 稅額 === 總計`；`fromSales` → `fromTotal` 互為反函數（掃 1～5000）。
4. **列金額覆寫**：直接填 3000 生效（數量／單價不變），合計改為 3000、總計 3150；再改數量為 4 → 覆寫清除、金額回 20000、總計 21000。
5. **稅額覆寫**：稅額改 800 → 總計 10800，銷售額仍為 10000。
6. **課稅別**：切零稅率 → 稅額欄留白、總計 = 銷售額 10000；切回應稅 → 稅額 500、總計 10500。
7. **二聯式**：無統一編號、無銷售額合計與營業稅列，日期行仍在；數量 1 × 單價 1050 → 總計 1050、框外「內含稅額 $50」「銷售額 $1000」。
8. **跨類型稅制修正**：三聯式選零稅率後切二聯式 → 稅制回應稅、框外顯示內含稅額；總計 2000 → 「內含稅額 $95」「銷售額 $1905」；切回三聯式時 ✓ 在應稅格。
9. **固定五列與備註結構**：`item-name-0`～`4` 存在、`item-name-5` 不存在、發票內無按鈕；備註只有第 1、2 列為輸入框，第 3 列為「營業人蓋用統一發票專用章」印刷字格，第 4 列起為單一合併空白格（三聯式 rowspan 7、二聯式 4）。
10. **長字串不吃字**：50 字品名完整保留、無水平截斷、列高增長、表格不橫向溢出；視窗縮到 500px 與字級放大到 1.4rem 後重算高度，被裁切高度 ≤ 2px；備註欄同樣成立。
11. **小數一律整數元**：總計 999.99 → 1000／銷售額 952／稅額 48（不是 47.99000000000001），九格有 4 個數字；銷售額 1000.5 → 1001；列金額 100.5 → 101；稅額覆寫 50.5 → 51。
12. **負數不進入金額區**：總計 -100 → 三欄留白、九格無數字；列金額 -500 → 顯示 `0`，且合計歸零時不覆蓋既有的銷售額 1000／總計 1050；稅額 -9999 → 留白、總計不變成負數。
13. **期別與日期預設值**：期別年 = 當年民國年、期別月份 = 當期雙月（動態依系統日期，不寫死）、日期年 = 當年民國年、月與日空白；下拉六個選項文字為「一、二」…「十一、十二」；三格日期與期別年皆可改，兩個年份互不影響。
14. **只收阿拉伯數字**：期別年填 `abc` → 空白；日期月填 `9a` → `9`；日填 `2x` → `2`、`x5` → `5`；年填中文 → 空白。
15. **日期合法性驗證**：日期填 8 月 32 日 → 畫面顯示 8 月 31 日；月改為 2（民國 113／2024 閏年）→ 日自動夾成 29，年改為 114／2025 平年 → 日再自動夾成 28；月填 13 → 夾成 12。
16. **清除重填**：買受人／品項（含長品名、備註、金額覆寫）／金額全部歸零、九格只剩印刷單位字、稅制回應稅、期別回當年當期、日期年回當年且月日清空。
17. **大寫呈現**：`upper-digit-4` 為「壹」；數字色 `rgb(29, 78, 216)` 與印刷單位字 `rgb(107, 100, 20)` 不同色，數字字級較大、字重不低於單位字，數字＋單位整組在格內置中。
18. **紙本框線與印刷字**：外框四邊 2px、內線 1px；表頭與標籤格印刷字左右內距 > 8px（不貼齊格線）；「零稅率」三字連成一組置中。
19. **375px 窄螢幕**：統一編號 8 碼完整顯示不被裁；日期行獨立成行且仍置中於紙張寬度。
20. **鍵盤操作**：Tab 可依序聚焦兩個發票類型 tab，Enter 切換生效（統編欄隨之消失）。
21. **無執行期錯誤**：長品名 + 逐字輸入 + 連續縮放（1400→375→1400）+ 字級變動 + 切換聯式 + 清除重填的完整流程中，window／console／page error 皆為空，且不得出現 `ResizeObserver` 相關訊息；同時內容仍完整不被裁切（不得靠關掉自動增高過關）。
22. **金額千分位**：列金額／單價／銷售額／稅額／總計與二聯式框外的內含稅額／銷售額，離開聚焦後顯示千分位（如 `10,500`）；欄位取得 focus 時顯示純數字，blur 後才變回千分位；貼上含逗號字串（如 `10,500`）能正確解析成數字；單價允許小數且千分位只加在整數部分（如 `1,234.5`）；數量、期別年份、民國日期年月日不受影響。
23. **測試與檢查全過**：`npm test` 160 個單元／元件測試（`invoice.test.ts` 75、`InvoiceSheet.test.ts` 60、`App.test.ts` 25）、`npm run test:e2e` 29 個端對端測試、`npm run build`（`vue-tsc -b` + `vite build`）皆通過。
